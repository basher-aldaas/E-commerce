== notes
- The race is timing dependent: in this run app failed (exit=1, 'migrations'
  already exists), app2 migrated everything, app3 came late and found nothing
  to do. With `set -eu` in docker/entrypoint.sh a failed migrate ends the
  container before `serve`, so on an empty database an instance could die at
  startup. The seed (app:seed-if-empty) has the same check-then-insert race.
- After: one migrate + one seed, 21 tables, then app, app2, app3 start.
